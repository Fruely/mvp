# Specialist Access Enforcement Policy

## 1. Purpose

Этот документ фиксирует текущую продуктовую политику Freuly после перехода на **free profile + paid demand access**.

Ключевой принцип:

> Публичный базовый профиль не требует платной подписки. Платным является доступ к контактам клиентских заявок и дополнительные функции тарифов.

## 2. Публичный профиль

Новый специалист проходит:

`регистрация → draft → заполнение обязательных данных → публикация базового профиля`.

- Регистрация бесплатна.
- Публикация заполненного базового профиля бесплатна.
- Отсутствие Professional/Growth само по себе не должно скрывать опубликованный профиль.
- Профиль может быть ограничен по объективным основаниям: нарушение правил, недостоверные данные, блокировка, технические ограничения или продуктовая политика реакции на клиентские запросы.
- Старые `early_access` / `trialing` — legacy/transition статусы, а не публичный бесплатный тариф.

## 3. Контакты клиентской заявки

Контактные данные клиента — отдельный commercial entitlement.

Каноническое правило:

`can_view_client_contact = subscription_entitlement OR paid_request_entitlement OR persisted_valid_unlock`

До entitlement:
- PII клиента скрыт;
- специалисту показывается только безопасное превью, достаточное для оценки релевантности заявки.

После entitlement:
- Professional/Growth может дать доступ в рамках тарифа;
- без подписки конкретный request offer может быть куплен отдельно, если pay-per-lead доступен для этого потока;
- success redirect сам по себе не является подтверждением оплаты; authoritative proof приходит серверно через Stripe/webhook/grant.

## 4. Direct selection и redistribution

Если клиент выбрал конкретного специалиста:
1. этот специалист получает первую возможность обработать запрос;
2. при активном тарифе контакт может быть разблокирован по entitlement;
3. без тарифа может быть предложена разовая покупка заявки;
4. если специалист отказывается или offer истекает, запрос может быть перераспределён другим подходящим специалистам.

Поддерживаемые причины offer:
- `direct_selection`
- `matched`
- `redistributed`
- `manual`

Поддерживаемые lifecycle statuses:
- `offered`
- `viewed`
- `accepted`
- `paid`
- `declined`
- `expired`
- `fulfilled`

Отдельный UX для явного decline/автоматического expiry должен соответствовать этой политике; отсутствие такого UI не должно приводить к раскрытию PII.

## 5. Тарифы

- `basic` = Freuly Professional, 29 €/месяц.
- `premium` = Freuly Growth, 59 €/месяц.
- Автоматического повторного списания нет.
- Следующий период приобретается новым ручным checkout.
- Окончание тарифа прекращает тарифный entitlement к новым контактам после применимого lifecycle/grace, но **не должно само по себе снимать бесплатную публикацию базового профиля**.

## 6. Pay-per-lead

Разовый доступ:
- относится к конкретному request offer;
- не создаёт подписку;
- имеет server-authoritative цену;
- подтверждается серверно после платежа;
- может быть отозван/скорректирован при refund/dispute по действующей политике.

Direct pay-per-lead может быть защищён feature flag и считается доступным пользователю только тогда, когда runtime resolver возвращает `canPurchase: true`.

## 7. Grace / inactive

Grace относится к **тарифному доступу**, а не к праву существования публичного бесплатного профиля.

- `active` — текущий тарифный entitlement.
- `grace` / `grace_period` — временное сохранение тарифного доступа по lifecycle.
- `inactive` / `expired` — нет нового тарифного entitlement; специалист может использовать доступные разовые покупки заявок.
- уже легитимно открытые исторические контакты обрабатываются по текущей persisted-access policy.

## 8. Что нельзя делать

- Нельзя скрывать профиль только потому, что специалист не купил Professional/Growth.
- Нельзя обещать бесплатный контакт клиента вместе с бесплатным профилем.
- Нельзя открывать PII по browser flag, query param или непроверенному payment success.
- Нельзя считать pay-per-lead подпиской.
- Нельзя обещать гарантированное количество заявок, клиентов, заказов или доход.

## 9. Партнёрская программа

Referral attribution фиксируется при регистрации привлечённого специалиста, но бесплатная регистрация/публикация не создаёт комиссию.

Текущий qualified partner conversion:
- первая успешная месячная оплата Professional или Growth привлечённым специалистом;
- одна referral-комиссия на одного специалиста;
- разовая pay-per-lead покупка не создаёт партнёрскую комиссию.

## 10. Source of truth

Использовать:
- `specialist_plan` для тарифного lifecycle;
- `request_offers` для коммерческого offer lifecycle;
- payment/access grant для разового entitlement;
- `contact_unlocked_at` как persisted PII boundary прямого лида;
- серверный access resolver как каноническое решение.

Не выводить коммерческий доступ только из `is_visible`, `is_active`, plan label или старого legacy status.
