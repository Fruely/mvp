# Operator Dashboard Runbook

## 1. Назначение

Operator Dashboard — это рабочий слой Freuly Lead Machine для администратора.

Цель не в том, чтобы оператор разбирался в технических таблицах, а в том, чтобы он быстро понимал:

- что происходит на рынке;
- что нужно опубликовать;
- каких специалистов проверить;
- какое действие ведёт к заявке Freuly.

Главный принцип:

много данных — внутри системы;  
простое действие — для оператора.

---

## 2. Главные таблицы в Baserow

## 3. Operator Daily Actions

Это главная таблица оператора.

Она отвечает на вопрос:

Что сделать сегодня?

В ней собраны действия из трёх направлений:

- рынок и категории;
- публикации и контент;
- потенциальные специалисты.

Смотреть в первую очередь поля:

- Операторский приоритет
- Тип действия
- Краткий вывод
- Что сделать
- Почему важно
- Действие для лидогенерации
- Рекомендуемый канал
- Статус
- Категория
- Подкатегория
- Регион
- Город

Типы действий:

Работа с категорией — понять, где усиливать спрос или предложение.

Публикация контента — проверить и опубликовать готовый текст.

Проверить специалиста — проверить потенциального специалиста и решить, стоит ли контактировать.

Рабочий порядок:

1. Открыть Operator Daily Actions.
2. Отсортировать по приоритету.
3. Выполнить 3–5 верхних действий.
4. Если нужна детализация, открыть связанную таблицу:
   - Operator Category Opportunities;
   - Operator Content Tasks;
   - Operator Scout Prospects.
5. Обновить статус вручную, если действие выполнено.

Главное правило:

Оператор не анализирует рынок вручную.  
Оператор выполняет понятные действия, которые система уже подготовила.

## 4. Operator Category Opportunities

Эта таблица отвечает на вопрос:

Что сейчас делать по рынку?

Смотреть в первую очередь поля:

- Операторский приоритет
- Краткий вывод
- Что сделать
- Почему важно
- Действие для лидогенерации
- Рекомендуемый канал действия
- Сигналы спроса
- Сигналы предложения
- Оценка перспективности

Как читать:

Если спрос выше предложения:
- нужно искать специалистов;
- параллельно готовить клиентский контент.

Если предложение выше спроса:
- нужно вести клиентов к заявке через контент, SEO или тестовую рекламу.

Если есть и спрос, и предложение:
- можно тестировать полный цикл: публикация → заявка → специалист.

## 5. Operator Content Tasks

Эта таблица отвечает на вопрос:

Что публиковать?

Смотреть в первую очередь поля:

- Операторский приоритет
- Краткий вывод
- Что сделать
- Почему важно
- Действие для лидогенерации
- Канал
- Статус
- Тема
- Готовый текст
- CTA

Рабочий процесс:

1. Открыть задачи со статусом draft_ready.
2. Выбрать высокий или средний приоритет.
3. Проверить текст.
4. Адаптировать под канал.
5. Опубликовать.
6. Вести читателя к заявке Freuly или к созданию профиля специалиста.

Главная цель публикации:

не просто просмотры, а переход к заявке или регистрации специалиста.

## 6. Operator Scout Prospects

Эта таблица отвечает на вопрос:

Кого проверить и как контактировать?

Смотреть в первую очередь поля:

- Краткий вывод
- Что сделать
- Почему важно
- Действие для лидогенерации
- Рекомендуемый канал контакта
- Риск контакта
- Статус
- Статус контакта
- Описание услуги
- AI-оценка
- Источник

Рабочий процесс:

1. Проверить источник/профиль специалиста.
2. Убедиться, что специалист релевантен Freuly.
3. Проверить канал контакта.
4. Если всё подходит — добавить в outreach.
5. Связаться аккуратно через рекомендуемый публичный канал.
6. Обновить статус контакта.

Важно:

не делать массовую агрессивную рассылку.  
Контакт должен быть аккуратным и ручным.

## 7. Ежедневный порядок работы

Рекомендуемый порядок:

1. Открыть Operator Daily Actions.
2. Отсортировать по приоритету.
3. Выполнить 3–5 верхних действий.
4. Если действие связано с публикацией — открыть Operator Content Tasks.
5. Если действие связано со специалистом — открыть Operator Scout Prospects.
6. Если действие связано с категорией — открыть Operator Category Opportunities.
7. Обновить статусы в Baserow.

---

## 8. Как понимать цель системы

Market Radar не нужен ради сбора данных.

Его задача — помогать Freuly получать заявки.

Цепочка:

рыночный сигнал
→ понимание спроса/предложения
→ контент или поиск специалиста
→ заявка Freuly
→ специалист получает потенциального клиента

Главная метрика:

не количество строк в CRM, а количество качественных заявок специалистам.

## 9. Что оператору не нужно делать

Оператору не нужно:

- работать напрямую с Supabase;
- понимать технические поля;
- запускать SQL;
- менять структуру таблиц;
- интерпретировать сырые сигналы вручную.

Оператор работает с готовыми выводами:

- Краткий вывод
- Что сделать
- Почему важно
- Действие для лидогенерации

---

## 10. Когда звать основателя/технического ответственного

Звать, если:

- категория явно определилась неправильно;
- город определился неправильно;
- задача выглядит бессмысленной;
- специалист не подходит, но система поставила высокий приоритет;
- в таблице появились дубли;
- непонятно, куда ведёт действие для лидогенерации.
